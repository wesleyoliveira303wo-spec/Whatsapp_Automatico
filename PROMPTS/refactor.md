# Prompt: Refactor

**Purpose**: Guide Claude to perform safe, incremental refactoring while preserving behavior.

---

## 1. Situation
- Existing feature works but violates a coding standard, introduces duplication, or has performance concerns.
- The refactor should be *behavior preserving*; add/modify tests if needed.

---

## 2. Claude Workflow
1. **Identify target** – locate the file(s) to refactor (`[src/backend/services/lead.ts:12]`).
2. **Explain the issue** – one‑sentence description (e.g., "duplicate validation logic").
3. **Propose a refactor plan**:
   - List affected files.
   - Describe the new structure (e.g., extract utility function, introduce interface, replace loop with map).
4. **Ask for approval** before modifying any public API.
5. **Execute changes** using **Edit** (for existing files) or **Write** (new helper files).
6. **Run tests**; add tests for any new public contract.
7. **Commit** with `refactor:` prefix.
8. **Update documentation** if the public API changes.

---

## 3. Refactor Checklist
- [ ] No behavior change (all existing tests pass).
- [ ] No new lint warnings.
- [ ] No `any` introduced.
- [ ] Updated `CHANGELOG.md` with a `refactor:` entry.
- [ ] Documentation reflects new usage (if applicable).
