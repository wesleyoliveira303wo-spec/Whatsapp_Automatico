# Prompt: Testing

**Goal**: Provide a consistent workflow for adding or updating tests (unit, integration, E2E) for new or modified functionality.

---

## 1. Identify Test Type

- **Unit** – pure functions, services, utilities.
- **Integration** – API routes, database interactions (use an in‑memory SQLite DB via Prisma).
- **E2E** – user flows in the browser; use Playwright.

---

## 2. Steps for Claude

1. **Locate the feature** – determine which files are impacted.
2. **Determine existing test coverage** – run `npm test -- --coverage` or inspect `coverage/`.
3. **Write test skeleton**:
   - For unit tests, import the target function and mock dependencies with `jest.mock`.
   - For integration, spin up a test server (`supertest`) and use a temporary DB.
   - For E2E, write a Playwright spec that navigates the UI, performs the action, and asserts the outcome.
4. **Add assertions** covering both success and failure paths.
5. **Run the full test suite** to ensure no regressions.
6. **Update coverage badge** in the `README.md` (optional).
7. **Commit** with `test:` prefix and include relevant test file paths.

---

## 3. Checklist

- [ ] Tests fail before implementation (red‑green cycle).
- [ ] All new code paths exercised.
- [ ] No `console.log` left in test files.
- [ ] Coverage threshold (80% total, 90% for new modules) met.
- [ ] CI passes with `npm test`.
- [ ] Documentation updated if new test scripts added.
