# Prompt: Documentation

**Purpose**: Guide Claude to write or update project documentation such as READMEs, architecture diagrams, or design decisions.

---

## 1. When to Use
- Adding a new feature that introduces a public API.
- Updating an existing component that changes its behavior.
- Creating a design decision entry.

---

## 2. Steps
1. Identify the affected documentation file (e.g., `API_SPECIFICATION.md`).
2. Summarize the change in one sentence.
3. Insert a new markdown section with a clear heading.
4. Add examples or code snippets if relevant.
5. Make sure the Table of Contents (if present) is updated.
6. Run any documentation linter (`npm run docs:lint`).

---

## 3. Checklist
- [ ] Section added with proper heading level.
- [ ] Links to related files are correct.
- [ ] No dangling internal anchors.
- [ ] Updated Table of Contents.
- [ ] Commit with `docs:` prefix.
