# Prompt: Code Review

**Purpose**: Provide a systematic approach for Claude to review a pull request or a set of changes.

---

## 1. Scope

- Review the diff provided (or the PR URL via `gh` CLI).
- Focus on correctness, security, performance, and adherence to `CODING_STANDARDS.md`.
- Include a brief summary of findings grouped by severity.

---

## 2. Review Process

1. **Gather context**:
   - Load the changed files (`Read` tool).
   - Identify affected layers (frontend, backend, DB).
2. **Static analysis**:
   - Look for anti‑patterns (`eval`, raw SQL, insecure string interpolation).
   - Verify that all new endpoints have OpenAPI entries.
   - Check that new models include `tenantId`.
3. **Security checks**:
   - Validate input sanitisation (Zod schemas).
   - Ensure no secrets are hard coded.
   - Confirm proper authentication/authorization.
4. **Performance considerations**:
   - Detect N+1 queries (look for `findMany` without `include`).
   - Flag heavy loops in hot paths.
5. **Write review comments**:
   - Use the `/code-review` skill if available, otherwise output a markdown list.
   - Mark each comment with the file and line number.
6. **Summary**:
   - Provide an overall rating (e.g., **Approve**, **Needs changes**).
   - List any required follow‑up tasks.

---

## 3. Review Template Example

```markdown
## Summary

- ✅ Overall good; passes all checks.
- ⚠️ Minor issues:
  - `src/backend/services/campaign.ts:78` – missing `await` on async call.
  - `src/frontend/components/LeadTable.tsx:42` – uses `any` for row type.
- ❌ Critical:
  - `src/backend/infra/whatsappProvider.ts:15` – logs WhatsApp token in plain text.

## Recommendations

- Replace `any` with proper `LeadRow` interface.
- Add proper secret handling for WhatsApp token.
- Add unit test for `CampaignService.schedule`.
```
