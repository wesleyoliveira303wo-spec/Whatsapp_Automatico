Design System · v1.0

O sistema visual do Francis

Extraído da Dashboard de Conversas aprovada. Esta é a fonte da verdade para toda tela nova — nenhuma exceção sem justificativa registrada aqui.

1. Por que a tela de Conversas funciona

Um acento, o resto neutro. Verde-teal (#0E6E52) aparece só onde exige ação: botão primário, bolha enviada, badge de não lidas, item ativo do rail. Todo o resto é escala de cinza-verde. Isso é o que permite olhar a tela por 8h sem cansar — não há disputa visual constante.

Estrutura por espaço, não por borda. As quatro faixas (rail/lista/chat/contexto) se separam por fundo (3 tons de neutro quase idênticos) + 1 divisória de 1px — nunca por moldura em cada elemento.

Selos em tinta translúcida. Todo selo de estado usa a cor semântica a ~12% de opacidade de fundo com o texto na versão escura da mesma cor — nunca cor sólida cheia, exceto no botão primário.

Hierarquia por peso e cor, não por tamanho. 2–3 tamanhos de texto por região; a diferença entre primário/secundário/terciário é peso (600/500/400) e cor (#16211C / #3E4A44 / #5C6B64).

Ritmo previsível. Linhas de lista com altura constante; cards com a mesma anatomia em toda tela. O olho aprende o padrão uma vez.

3. Tipografia

Instrument Sans em toda a interface. Escala fixa — nunca inventar um tamanho fora desta lista:

17px / 600 / -0.025emTítulo de painel/coluna
14.5–15.5px / 600Título de card, nome primário
13–13.5px / 400–500Corpo, texto de mensagem
12–12.5px / 500Texto secundário, botões pequenos
11–11.5px / 500–600Terciário: timestamp, selo, rótulo uppercase

4. Espaçamento, raio e elevação

  • Grid base de 4px. Passos usados: 4·6·8·10·11·12·14·16·18·20·24·32.
  • Raio pequeno 7–9px (botões, chips, inputs); raio de superfície 12px, único e fixo (cards, linhas de lista, menus, bolhas de mensagem, containers) — não 11, 13 ou 14px; 999px para pílulas e avatares.
  • Altura de botão de ação (CTA) 34px, única e fixa — primário e secundário. Botões de ícone (utilitários do rail, cabeçalho, composer) seguem sua própria escala quadrada (28/32/34/38px conforme o contexto) e não entram nesta regra.
  • Sombra só para o que flutua de verdade: menus suspensos (0 12px 32px rgba(16,24,20,.14)), botão flutuante, botão primário (0 1px 2px sutil). Cards de conteúdo nunca têm sombra — só fundo + 1px de borda ou nada.
  • Densidade: compacto dentro de um grupo (avatar/nome/prévia quase colados), respiro entre grupos (12–24px).

5. Casca fixa (repete em toda tela)

Header global (48px) + rail de sessão (56px, só ícones) são idênticos, pixel a pixel, em Conversas / Pipeline / Analytics / IA / Configurações. Só a área de conteúdo muda. Isso é o que garante a sensação de "um único produto".

  • Header: marca à esquerda; nome da sessão + ponto de status à direita.
  • Rail: marca da sessão (= botão voltar ao Workspace) → Conversas / Pipeline / Analytics / IA → spacer → tema → Configurações (menu de conta).
  • Item ativo do rail: fundo rgba(14,110,82,.10), ícone #0E6E52. Inativo: #5C6B64, hover #E9EAE5.

6. Componentes-padrão reaproveitados

  • Badge de estado: pílula 20–22px de altura, ponto de 5px + texto 11–11.5px/600, fundo translúcido.
  • Botão primário: #0E6E52, texto branco 600, raio 9px, sombra sutil, hover #0B5C45.
  • Botão secundário: borda #E6E7E3, fundo branco, hover #F5F6F3.
  • Card: fundo branco ou #FAFAF9, raio 12px, sem sombra, separado por espaço/borda de 1px — nunca moldura própria pesada.
  • Input/textarea: raio 9–10px, borda #E6E7E3, foco 0 0 0 3px rgba(14,110,82,.10) + borda #B9D3C8.
  • Tabela: sem grade completa — só divisória horizontal 1px entre linhas, cabeçalho 11px uppercase/600/#5C6B64.
  • Estado vazio: ícone 40px em quadrado neutro + título 600 + descrição secundária — tom de convite.
  • Skeleton: blocos #EFF0EC com pulso sutil, nunca spinner central.

7. Handoff para desenvolvimento

Os 5 arquivos de referência (Francis Conversas, Francis Pipeline, Francis Analytics, Francis Cérebro da IA, Francis Configurações) são HTML/CSS-inline navegáveis — a fonte de verdade pixel a pixel. Para portar ao código React existente:

  • Os valores das seções 2–4 acima tornam-se os tokens do projeto (Tailwind theme ou CSS vars) — não introduzir cor/raio/sombra fora desta lista.
  • Nenhuma funcionalidade da PRODUCT_DESIGN_SPECIFICATION.md foi removida em nenhuma tela; onde algo saiu do lugar, o novo lugar está descrito na própria tela (ex.: e-mail/cargo/trocar senha/sair migraram para o menu de conta no rail).
  • Os componentes de UI existentes (Button, Badge, Card, Table, Dialog etc.) podem ser restyled em vez de recriados — a função de cada um não muda, só a aparência.
  • Estados de carregamento/vazio/erro de cada tela seguem o mesmo padrão visual descrito na seção 6 — implementar com os componentes de esqueleto e estado vazio já existentes, restilizados.
  • Responsividade: mesmos 3 pontos de corte da spec (<1024 / 1024–1279 / ≥1280), já resolvidos na tela de Conversas como referência de padrão a replicar onde aplicável.

Este documento evolui junto com o produto — qualquer nova tela deve nascer lendo-o primeiro, não copiando a tela mais recente.
