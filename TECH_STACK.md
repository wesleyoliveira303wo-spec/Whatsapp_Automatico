# Technical Stack

This document enumerates the technologies, libraries, and tools selected for the **WhatsApp Automation Platform**. Choices are guided by the project's objectives, the team's skill set, and long‑term maintainability.

---

## 1. Language & Runtime
| Layer | Language | Runtime |
|-------|----------|---------|
| Frontend | TypeScript (React) | Node.js v20 (Next.js server) |
| Backend | TypeScript (Node.js) | Node.js v20 |
| Scripting / DevOps | Bash, PowerShell, Dockerfile | Linux/macOS/Windows |

## 2. Frontend Stack
| Category | Technology | Reason |
|----------|------------|--------|
| Framework | **Next.js** (React, SSR) | SEO friendly, file‑based routing, API routes. |
| UI Library | **shadcn/ui** + **Tailwind CSS** | Consistent design system, themable, low‑boilerplate. |
| State | **React Query** (data fetching) & **Zustand** (global UI state) | Declarative, cache‑aware, simple API. |
| Forms | **React Hook Form** + **Zod** resolver | Type‑safe validation and minimal re‑renders. |
| Testing | **Jest** + **Testing Library** (unit & integration) | Community standard, good TS support. |
| E2E | **Playwright** | Cross‑browser automation, powerful selectors. |
| Lint/Format | **ESLint** (Airbnb) + **Prettier** | Enforce style, catch bugs early. |
| Type Checking | **TypeScript 5.x** with `strict` mode | Compile‑time safety. |

## 3. Backend Stack
| Category | Technology | Reason |
|----------|------------|--------|
| Server | **Express** (TypeScript) | Minimal, fast, easy to extend. |
| GraphQL | **Apollo Server** | Flexible client queries, schema‑first approach. |
| ORM | **Prisma** | Type‑safe DB access, migrations, auto‑generated TS types. |
| Queue | **BullMQ** (Redis) | Robust job handling, retries, rate limiting. |
| Cache | **Redis** (standalone) | Session store, token cache, cheap pub/sub. |
| Authentication | **JWT** (RS256) + **bcrypt** | Stateless, widely supported, secure password hashing. |
| AI Integration | **Claude API** (HTTPS) wrapped in a service layer | Best‑in‑class LLM, easy to swap later. |
| WebSocket | **Socket.io** (server) + client lib | Real‑time chat updates. |
| Observability | **OpenTelemetry** (Node SDK) + **Winston** for logs | Vendor‑agnostic tracing, structured logs. |
| Testing | **Jest** + **Supertest** for API endpoints | End‑to‑end request testing. |
| Security | **helmet**, **hpp**, **csurf**, **express-rate-limit** | OWASP top‑10 mitigations. |

## 4. DevOps & CI/CD
| Tool | Purpose |
|------|---------|
| **GitHub Actions** | Lint, test, build Docker images, publish releases. |
| **Docker** | Containerization for dev (Compose) and prod (Kubernetes). |
| **Docker Compose** | Local stack (Postgres, Redis, API, Frontend). |

| **OpenAPI Generator** (optional) | Generate API client SDKs from spec. |

## 7. Cloud Provider (Target)
The platform is cloud‑agnostic but the MVP targets **AWS** for managed PostgreSQL (RDS), Redis (Elasticache), and Kubernetes (EKS). The IaC files are kept generic to allow migration to GCP or Azure.
